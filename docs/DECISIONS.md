# Architecture, Data Cleaning & Modelling Decisions (`DECISIONS.md`)

| ID | Decision | Alternatives Considered | Why | Evidence (Verified in `qwiklabs-gcp-04-ec3596addc43`) |
|---|---|---|---|---|
| **DEC-001** | **Four-Layer Medallion Architecture in BigQuery (`a4i_climate` → `a4i_core` → `a4i_semantic` / `a4i_ml`)** | Query raw `a4i_climate` directly from ML models and MCP Toolbox tools | Isolates raw data anomalies (`-9999.0` sentinels, unpadded FIPS, 56 non-target cities, 1 Hz road autocorrelation) in a single audited `a4i_core` layer and provides self-documenting, contract-tested views/TVFs in `a4i_semantic` and `a4i_ml`. | `sql/tests/02_validate_core_and_before_after.sql`: all 13 `validate.sql` checks pass on `a4i_core` (whereas 3 failed on raw `a4i_climate`). |
| **DEC-002** | **Pad `geo_id` (`LPAD(CAST(geo_id AS STRING), 11, '0')`) and convert `< 0` sentinels (`-9999.0`) to `NULL` in `a4i_core.tracts`, then median-impute `feat_*` columns in `a4i_ml.tracts_enriched`** | Drop tracts with `-9999.0` sentinels or pass raw numeric values into BQML | Dropping tracts creates spatial holes across Atlanta; passing `-9999.0` into `LINEAR_REG` catastrophically skews regression weights and `ML.EXPLAIN_PREDICT` attributions. Preserving `NULL` in `a4i_core`/`a4i_semantic` while exposing median-imputed `feat_*` columns in `a4i_ml.tracts_enriched` keeps planner tables honest and ML features complete. | In `a4i_climate.tract_demographics` (Atlanta bounding box, `353` tracts): `median_income = -9999.0` in **3** tracts (`0` after cleaning) and `median_year_structure_built = -9999.0` in **2** tracts (`0` after cleaning). `a4i_ml.tracts_enriched` has `0` NULLs and `0` sentinels across all `feat_*` columns. |
| **DEC-003** | **Join ACS 2020 5-Year (`censustract_2020_5yr`) for Age 65+ and US Census TIGER (`us_census_tracts_national`) for Tract Polygons & Land/Water Area** | Rely only on `tract_lat`/`tract_lon` point centroids and `median_age` | Point centroids cannot compute area-weighted catchment populations or true population/housing density (`per km²`), and `median_age` hides senior concentration (`65+` is a primary heat mortality risk factor). Both public datasets are US Federal Government Public Domain (17 U.S.C. § 105). | `a4i_core.tracts` achieved a **100% join match (`353 / 353` tracts)** against both `bigquery-public-data.census_bureau_acs.censustract_2020_5yr` and `bigquery-public-data.geo_census_tracts.us_census_tracts_national`, with `0` NULL `pop_density_km2` rows. |
| **DEC-004** | **Aggregate 1 Hz mobile traverse points (`23,386` rows) into `geohash-7` (~150 m) cells (`2,020` rows) and assign `geohash-5` (~4.9 km) `spatial_block_id` (`22` blocks)** | Random row-level train/eval split on `23,386` 1 Hz points | Consecutive 1 Hz readings along a road are ~5–15 m apart (`avg 8.21 neighbors within 20m`, max `119` at intersections). Random row-level splitting leaks adjacent points across train and eval (`R² ≈ 0.98` illusion). Aggregating to `geohash-7` cells (`fact_heat_cell`) and holding out whole `geohash-5` spatial blocks prevents spatial autocorrelation leakage. | `a4i_core.heat_readings` (`23,386` rows, `campaign_mean_f = 82.062°F`) collapses into `2,020` `geohash-7` cells across `22` `geohash-5` blocks (`heat_offset_f` range `-5.79°F` to `+7.70°F`). |
| **DEC-005** | **Exclude Race/Ethnicity from `a4i_core`, `a4i_semantic.dim_tract`, and `a4i_ml`; Define Vulnerability Index Using 4 Non-Racial ACS Factors** | Use CDC SVI `RPL_THEMES` or race percentages as model/ranking features | Non-negotiable rule #4: race/ethnicity must never be a model input and may only appear in the post-hoc equity audit of recommended outputs. | `a4i_semantic.dim_tract.vulnerability_pct` is an equal-weight `PERCENT_RANK()` composite of `poverty_rate`, `no_vehicle_rate`, `pct_age_65_plus`, and inverse `median_income` (`353` tracts partitioned into quartile tiers `1..4`). |
| **DEC-006** | **Separate Spatial Where (`Heat Watch` → `fact_heat_cell`) from Temporal How Often (`GHCN` → `fact_city_heat_day` & `site_hot_days(offset_f)`)** | Estimate annual hot days from Heat Watch `observed_at` timestamps | Heat Watch is a single-day spatial snapshot (`observed_at` is `100%` NULL in Atlanta: `23,386 / 23,386` rows). GHCN daily station records (`17,452` station-days across 7 Atlanta stations, `2019–2025`, `2,557` distinct calendar days) provide the multi-year temporal baseline. | `a4i_semantic.site_hot_days(4.5)` combines a site's `+4.5°F` spatial offset with `2,557` GHCN city-days (`43.9` city days/yr `>=90°F` → `89.3` projected site days/yr `>=90°F` and `+28.7` extra days/yr `>=95°F`). |
| **DEC-007** | **Centralize ML Feature Assembly & Footprint Refusal Gate in `a4i_ml.point_features(pts)`** | Duplicate feature-engineering SQL across training scripts and Python agent tools | Guaranteeing zero train/serve skew requires a single parameterized TVF (`a4i_ml.point_features`) used at both training time and `ML.EXPLAIN_PREDICT` serving time. Including `nearest_reading_m` and `in_footprint` (`<= 500 m` from a campaign reading) enforces honest refusal outside the campaign footprint. | Verified on 3 test coordinates: on-route (`33.843635, -84.381345` → `0.0 m`, `in_footprint = true`), between-routes (`33.81, -84.44` → `449.7 m`, `in_footprint = true`), and Marietta out-of-footprint (`33.9526, -84.5499` → `12,275.3 m`, `in_footprint = false`). |
| **DEC-008** | **External Data License Gate: Reject Unlicensed Municipal Cooling Center Lists; Approve Only US Federal Public Domain Layers (USGS NLCD / EPA EnviroAtlas)** | Scrape City of Atlanta ArcGIS Open Data recreation centers or OpenStreetMap features | Challenge rule #9 strictly requires Public Domain / CC0 / US Federal Government works and forbids ODbL (OpenStreetMap) and unstated municipal licenses. City of Atlanta ArcGIS portals lack an explicit CC0/PD dedication, whereas USGS NLCD Imperviousness & USFS Tree Canopy (`mrlc.gov`) are 17 U.S.C. § 105 US Government Public Domain. | Documented in Stage 5 External Data Audit; no unlicensed municipal or OSM tables loaded into BigQuery. |
| **DEC-009** | **Train `a4i_ml.offset_model_v1` (`LINEAR_REG`) on `a4i_ml.train_cells` (`1,862` cells with `n_readings >= 3`) Using Balanced `geohash-5` Spatial-Block Holdout (`MOD(ABS(FARM_FINGERPRINT(block_id)), 5) = 3`)** | Random row-level train/eval split or hash fold `0` (`+0.80 °F` mean shift) | Random splits leak across 1 Hz adjacent road readings; hash fold `0` had a `+0.80 °F` train/eval mean shift (`+0.604 °F` vs `-0.191 °F`), whereas fold `3` holds out `484` cells (`26.0%`) across `6` full `geohash-5` (~5 km) blocks with balanced means (`-0.090 °F` eval vs `+0.008 °F` train). | `a4i_ml.offset_model_v1` beats the predict-zero baseline on held-out spatial blocks (`MAE = 1.254 °F` vs `1.355 °F` baseline, `RMSE = 1.542 °F` vs `1.622 °F` baseline, `R² = 0.094`, `explained_variance = 0.118`) with zero drive-day temperature leakage and zero race columns. |
| **DEC-010** | **Pre-Compute `a4i_ml.grid_predictions` (`5,618` ~250 m Candidate Grid Points) and Select Top 3 Cooling Centers by Hazard × Walkable Vulnerability with Greedy `>= 2.0 km` Spacing (`sql/serve/rank_sites.sql`)** | Rank by heat offset alone or pick top 3 adjacent grid points | Heat-only ranking clusters all 3 sites inside a single block; greedy `>= 2.0 km` spacing selects 3 distinct high-need neighborhoods without overlapping 1.5 km walking catchments. | Selects Site #1 Venetian Hills/Oakland City (`13121007603`, unmeasured, `+1.28°F`, `56.4%` no-car), Site #2 West End/Ashview Heights (`13121004200`, measured, `+1.49°F`, `46.7%` no-car), and Site #3 Mechanicsville/Summerhill (`13121004800`, unmeasured, `+1.35°F`, `24.2%` 65+, `38.0%` no-car), reaching `52,429` residents (`5,369` seniors 65+, `6,372` car-free HHs) within `1.5 km`. |
| **DEC-011** | **Run Post-Hoc Equity Audit (`sql/audit/audit.sql`) Comparing the Top 3 Recommended Tracts Against `a4i_semantic.audit_city_baseline` + Post-Hoc ACS Racial Composition Check** | Include race as a model/ranking input or skip outcome audit | Race is strictly excluded from `a4i_core.tracts`, `a4i_ml.offset_model_v1`, and site ranking. Post-hoc audit verifies the selected cooling-center tracts reach higher-need communities than the citywide baseline. | Recommended tracts have `6.12x` the citywide no-vehicle rate (`50.41%` vs `8.23%`), `3.16x` the poverty rate (`44.05%` vs `13.95%`), `1.56x` the `65+` senior share (`19.44%` vs `12.47%`), `$17,853` vs `$75,714` median income (`0.24x`), and `90.81%` vs `41.66%` Black residents (`2.18x`). |
| **DEC-012** | **Three-Service Decoupled Cloud Run Architecture (`heat-toolbox` MCP + `heat-planner-api` ADK Agent + `heat-ui` Custom Frontend)** | Monolithic web application embedding BigQuery credentials and SQL execution directly in UI server | Decoupling enforces least-privilege IAM service boundaries (`toolbox-sa`, `heat-agent-sa`, `heat-ui-sa`), isolates BigQuery ML and semantic queries behind a managed MCP server (`heat-toolbox`), and allows independent horizontal scaling, automated contract testing, and frontend presentation iteration. | Verified on Cloud Run: `heat-toolbox` (`toolbox-sa`, port 8080), `heat-planner-api` (`heat-agent-sa`, port 8000), and `heat-ui` / `urban-heat-ui` (`heat-ui-sa`, port 3000) communicating via authenticated OIDC identity tokens and VPC network routing. |
| **DEC-013** | **Adopt Gemini 3 (`gemini-3-flash-preview`) for Low-Latency Zero-Shot Routing and Grounded Narrative Generation** | Gemini 1.5 Pro or legacy rule-based string templates | `gemini-3-flash-preview` delivers sub-second intent classification and robust structured JSON serialization, meeting the strict <5 s end-to-end planning latency budget while guaranteeing deterministic grounding verification against tool outputs. | Intent classification and proposal narration complete in ~1.2 s per turn, consistently extracting spatial coordinates, candidate limits, and citing exact `[Pn]` provenance tags without numeric hallucination. |
| **DEC-014** | **Draft-Then-Published Contracts Pattern for Multi-Agent and Frontend/Backend Decoupling** | Ad-hoc Python dictionaries or unversioned HTTP JSON payloads | Formal JSON schemas (`AgentApiResponse`, `PlacementRecommendation`, `VizSpec`, `DataResult`, `Provenance`) in `docs/contracts/` enable parallel frontend and backend engineering, deterministic Pydantic schema validation, and early mocking against golden city samples before live deployment. | Validated in `agent/tests/test_contracts.py` and `ui_service/tests/test_viz_builder.py` against `docs/contracts/samples/site_selection_atlanta.json` and `explain_location_atlanta.json`. |

| **DEC-015** | **heat-ui draws only what a deterministic `VizSpec` says, built from the agent API response (`ui_service/viz_builder.py`)** | Let the LLM write chart/map specs, or have the browser compute numbers | Numbers on screen are the verified numbers the agent returned, never recomputed or invented; costs stay `[COST]`. Easy to test without a model. | `ui_service/tests/test_viz_builder.py`; `docs/contracts/viz_spec.schema.json`. |
| **DEC-016** | **Retire the P4 `app/` planner and `DEPLOY_P4.md`** | Keep both UIs | PR #11 replaced the legacy `agent/tools.py` functions `app/` depended on, so it no longer ran; heat-ui covers the same four screens against the new agent API. | `app/data.py` imported `rank_candidate_sites`, `audit_equity`, `get_city_centroid` from `agent/tools.py`, none of which exist after PR #11. |
